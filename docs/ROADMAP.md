# 路线图

Iris 的方向是本地优先、Agent 可调用的多模态创作工作台。用户可从描述或已有素材出发，生成、修改、选择和交付作品。本文介绍当前能力与后续方向；版本变化见 [变更记录](../CHANGELOG.md)。

## 当前状态

本文对应 **Iris 0.2.7**，发布状态见 [README](../README.md)。包名为 `@mokuyoaxis/dsh-iris`，同时提供 DSH 插件与独立 CLI；本版增加截图修复、实例运行时、持久图片流程、本地 API 和 Core Skill 安装，详见 [0.2.7 发布说明](releases/0.2.7.md)。

- 图片生成、Artifact ID 看图/OCR/定位和聊天改图，支持按模型配置图片协议。
- 持久图片导入与原生 Qwen 改图；六类功能可选自动池、手选或停用，宿主视觉需明确启用。0.2.5 建立的 12 个准确 DSH 版本范围保持。
- 视频、S2V、TTS、转写与音乐生成，共用任务、音频/视频作品和导出入口；音乐遵守当前允许范围并明确音乐协议。
- DSH 连接引用、模型用途确认、按需目录快照与精确模型不存在隔离；能力检测和高级分区默认折叠，实测单独确认费用。
- 三项 Agent Skills 分别指导单步操作、多步骤创作和界面验收；配乐与检查按用户目标加入。
- 提示词的忠实整理、明确改写、可选建议与预览；完整同步媒体结果缓存后的交付恢复。
- 工作台全媒体筛选、分页、跨页选择和下载，CLI 的配置、查询与可恢复维护。

DSH与CLI共用Task和Artifact，同一数据根只允许一个写者。纯视觉和提示词预览不自动创建媒体任务；Core与Model Port仍是内部契约。Node.js最低22.0.0。0.2.5恢复旧宿主的当前功能，并覆盖12个准确DSH版本；具体版本和历史范围见 [兼容矩阵](DSH_COMPATIBILITY.md)。

宿主兼容继续集中在Adapter与客户端桥接。后续DSH更新优先检查实际API、工具/附件交付和输入区契约，复用同一验收入口扩充版本矩阵，避免让旧用户长期停留在缺少新功能的Iris分支。

## 0.2.7 基础设施与 0.3.0 方向

宿主 HTML 截图已适配浏览器返回的 PNG 数据，并增加实际监听地址解析和用户主动触发的截图自检，见 [0.2.7 发布说明](releases/0.2.7.md)与 [宿主诊断](HOST_DOCTOR.md#截图地址与主动自检027)。

0.3 基础设施已接入首批 [内部应用运行时](CORE_RUNTIME_CONTRACT.md#应用运行时装配)与 [固定改图流程](IMAGE_FLOW.md)：实例写队列、稳定 Run/步骤与 Task 绑定、原任务/比较图恢复、引用保护和明确选择/导出。

[DSH Core 装配](DSH_RUNTIME.md)也已迁入实例：写入共用应用队列，连接解析引用、观察器和启动接管由插件持有，卸载等待在途操作。原根与业务保持；legacy 配置等存储仍未实例化，Flow 尚未接入 DSH 工作台。

0.2.7 已有 [I4A 默认只读 API](LOCAL_API.md)与 [I4B 本地创建](LOCAL_CREATION.md)：显式回环监听、Bearer/Host/Origin、受控图片，以及新空根主动启用的上传/Run 创建和持久 Key 身份接回。GET 不执行步骤，本地创建也不生成；有限执行/取消与 Operation 仍按 [API 契约](LOCAL_API_CONTRACT.md)继续。

源码树保留 [面向 0.3.0 的独立 Web Demo](WEB_PROTOTYPE.md)，用于说明输入、状态、比较与选择的操作方向。当前只消费演示数据，不连接模型、不计费，也未接入 API；界面与交互细节在 **0.3.0 阶段迭代**。未发布执行服务已有单独验收，真实工作台当前支持媒体只读与连接管理；页面创作、持久选择和通用 Recipe 继续按下方队列推进，没有已承诺的发布日期。

## 近期优先：真实使用验收

**未发布源码进展**：[Core 工作台](LOCAL_WEB.md)通过显式 `web serve` 显示持久历史、原图/结果与已选作品下载；可主动开启连接中心，自由命名并选择功能/工具权限、导出配置和撤销授权。[Core 服务](CORE_SERVICE.md)提供持久 Operation、单根 runner、有限执行/停止与授权 harness 桥；同一服务可显式组合连接管理与执行。页面媒体操作仍只读，npm 0.2.7 尚不含这些新入口。

连接名目采用用户建档和 MCP 客户端声明，不扫盘或按品牌白名单限制。源码已支持纯数据模板导入及按连接有效工具交付 Skill，复用显式安装器；下一步完善真实 Web 创作和全媒体分组。客户端身份声明与媒体实测分别展示。

[通用 MCP](MCP.md)已有 stdio/Streamable HTTP、generic 默认连接、明确功能/工具范围和配置导出，现仅暴露固定图片编辑流程。后续按现有 Core 的真实受理/恢复/交付能力逐组接入生图、视频、语音、音乐、转写和视觉，由用户选择；不因客户端连接成功就视为全媒体已覆盖。

优先完善图片创作与配乐、短片素材准备等完整流程：复用已有作品、按需生成、试听或查看结果，再导出可继续处理的素材。分别交付音视频素材不等于自动混音成片。

持续改进浏览器/移动端体验、模型配置说明和异步任务重启后的接管。音乐当前支持Chat Completions内嵌音频接口；新增音乐来源按具体协议与实际需求适配，不要求用户使用特定个人网关。

已有完整同步结果时，交付失败可以恢复缓存；缺少缓存的旧任务和过期URL不能保证恢复，详见 [同步交付恢复](SYNC_DELIVERY_RECOVERY.md)。作品管理和可恢复隔离见 [工作台作品管理](WORKBENCH_ARTIFACTS.md)。

DSH 工作台与 Headless CLI 共用 Core 的可恢复隔离和恢复入口，操作见 [CLI 管理](CLI_MANAGEMENT.md)。legacy `outputs/` 的删除仍永久生效；Core 回收区的删除可恢复，尚未提供永久 purge。两种行为在工作台分别显示，操作前应确认作品来源。

## 后续功能方向

### 后续 0.2.x

- 图片创作的原图/新版并排对比与版本选择；0.2.4已提供持久图片导入和原生Qwen改图。
- 适配其他协议，包括原生 Gemini、Fal 和后续 Replicate；网关兼容接口与原生协议接入分别验证；
- 按实际需求增加音乐来源、可控参数和音视频衔接；已有音乐生成入口见 [音乐生成](MUSIC.md)；
- 收藏、标签与工作台搜索（CLI 及工作台过滤、分页、显式选择/批量下载已完成）；
- Artifact 关系边冻结 `retried-from` 类型，补全重试谱系（0.2.0 仅有 Task 级 `retriedFrom`）；
- Core 隔离内容的永久 purge（0.2.1 已开放可恢复隔离/恢复，legacy 永久删除保持原行为）；
- 鸢尾花与泡泡视觉身份；
- 有可用接口与实际需求后，补 Images 编辑、mask、多参考图或连续编辑；
- 在已有纯核心提示词实现上补共享 `prompt.optimize` Command 与 CLI 消费；DSH 负责草稿读取、预览和写回；
- 冻结中立 TextModel Port，把 Ollama、兼容文本端点及其他文本模型后端与媒体 Provider Catalog 分离，避免通用文本模型淹没 Iris 媒体模型界面；
- 接入 ComfyUI、本地 TTS 等本地媒体 Provider，并补齐 `auth: none`、`billing: none`、同步完成语义和本地/远程 UI 区分；
- 有可信价格来源后的成本与策略展示。
- 显式授权后的目录新模型跟随、新语音协议及磁盘占用管理；当前自动池不自动授权目录新增模型，也没有跨请求轮转。

### 0.3 及以后

## 兼容性与限制

- Iris 0.2.x 的 Node.js 最低版本为 22.0.0；DSH 要求更高版本时以 DSH 为准。
- 图片处理依赖 `sharp`；视频文件抽帧依赖 `ffmpeg`、`ffprobe`，摘要复用既有 Core 帧时无需这两个工具。独立 HTML 截图需要显式提供 Chromium。
- DSH 仍处于快速演进期。单个 Host Port 可以降级，但 DSH 若改变插件加载协议，仍需更新 DSH Adapter。
- 模型发现只列出候选项；真实能力必须由用户显式验证。
- 原生 Windows/WSL 的完整 DSH 宿主冒烟仍待补充。
- Headless CLI 的媒体、视觉、S2V、HTML、配置、查询、批量、有界等待与 Core 隔离/恢复见 [CLI 管理](CLI_MANAGEMENT.md)。需要存储时显式指定绝对数据根，观察和等待不重新提交；Core 永久 purge 尚未开放。
- Responses 只支持同步单图；聊天改图只支持一张静态来源图片，输出尺寸与编辑精度由模型决定。

## 质量要求

- Core仅在明确未受理时切换候选；Music的有限502重发遵从本次配置并保留独立Task事实。
- 同一数据根不得出现两个写者；reader 不产生隐式写入。
- Core/CLI 在 DSH/Cordis 不可解析时仍能装载和运行本地动作。
- Task、Attempt 和 Artifact 不保存凭据、私有 URL 或不必要的宿主绝对路径。
- 每项新增行为需有失败路径测试；发布前执行打包、敏感信息和仓库外安装检查。

## 暂不计划

- 在插件中建设账号、多租户、计费或公网 SaaS；
- 由 DSH 插件隐式启动 daemon 或额外监听端口；
- 自动探测全部模型并产生不可见费用；
- 为没有真实调用方的 Provider 或 Host 预建空适配器；
- 在 Core 稳定前拆分多个 npm 包或重写技术栈。
