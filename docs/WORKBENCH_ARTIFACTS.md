# 工作台作品浏览与识别

状态：开发版已实现，尚未发布。已发布 npm 0.2.0 的作品库保持原行为。

Iris 工作台的作品库统一展示 Core 和旧版作品，包括图片、视频、音频和文本。默认按时间倒序排列，每页 24 个；使用上一页、下一页浏览全部作品。媒体类型、作品来源和产物类型可组合筛选，匹配总数与 Core/旧版计数均按当前筛选计算。切换筛选回到第一页，刷新保留页码和筛选；尾页因作品数量减少而超界时，回到最后一页。

Core 的原始输入 `host-input` 不出现在作品库。不可读取的 Core 条目局部跳过并提示；Core 整体暂时不可用时仍可浏览旧版作品，此时计数只含可读取来源。图片提供预览，视频、音频提供播放器，文本可以打开原文件。

## 从图片卡看图与 OCR

Core 图片卡的“看图”“OCR”按钮直接读取原 Artifact。点击即按默认配置运行，不需要复制路径、导出图片或转换格式。

- 看图默认详细描述，可在“更多选项”填写问题并重新识别。
- OCR 默认块高 1200、重叠 120 像素，可在“更多选项”修改；结果明确标记完成、部分完成或失败。
- 结果面板保留图片预览，正文可复制或下载为浏览器本地 `.txt` 文件。
- “取消识别”、关闭结果或切换分析会取消在途请求；迟到响应不会覆盖后续分析。
- 关闭结果保留作品页码和筛选，不自动写回对话或启动生成任务。

支持 Core PNG/JPEG/WebP/GIF。模型沿用当前 Iris 视觉能力分配及既有候选规则；主动点击识别会请求模型，浏览列表不会。旧版图片保留打开和既有工具的文件路径输入；旧版作品 ID 与 Core ID 不混用。

## 查询与完整性

工作台使用同源 `GET /iris/api/works`，参数为 `offset`、`limit`（默认 24，最多 60）、`media_type`（all/image/video/audio/text）、`source`（all/core/legacy）和 `kind`（all 或具体产物类型）。服务端先过滤、按时间及来源/ID 稳定排序，再统一分页，返回 `items/total/offset/limit/kinds/counts`；客户端不再拼接两个已经分页的结果。

目录查询复用已提交的 Manifest 与派生 Index，只读取元数据和文件大小，不反复读取视频等媒体的完整字节、不重建索引或取得 Core writer 租约。打开媒体、看图/OCR、CLI inspect/list/export 保留原有完整内容哈希核验；目录里显示的哈希不表示本次浏览已经重新核验了全部文件内容。

OCR 动作 JSON 附 `status/totalChunks/successfulChunks/failedChunks/skippedChunks`，便于界面表达完整度。识别正文不自动保存为 Core Artifact。

本轮未增加批量管理和 Core 删除入口。工作台已有旧版删除/清空语义保持原样；Core 的可恢复隔离与恢复仍使用 [CLI 管理命令](CLI_MANAGEMENT.md)。
