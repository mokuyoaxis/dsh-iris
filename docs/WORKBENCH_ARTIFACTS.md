# 工作台作品浏览、识别与管理

状态：**Iris 0.2.1**。

Iris 工作台的作品库统一展示 Core 和旧版作品，包括图片、视频、音频和文本。默认按时间倒序排列，每页 24 个；使用上一页、下一页浏览全部作品。媒体类型、作品来源和产物类型可组合筛选，匹配总数与 Core/旧版计数均按当前筛选计算。切换筛选回到第一页，刷新保留页码和筛选；尾页因作品数量减少而超界时，回到最后一页。

Core 的原始输入 `host-input` 不出现在作品库。不可读取的 Core 条目局部跳过并提示；Core 整体暂时不可用时仍可浏览旧版作品，此时计数只含可读取来源。图片提供预览，视频、音频提供播放器，文本可以打开原文件。

## 从图片卡看图与 OCR

Core 图片卡的“看图”“OCR”按钮直接读取原 Artifact。点击即按默认配置运行，不需要复制路径、导出图片或转换格式。

- 看图默认详细描述，可在“更多选项”填写问题并重新识别。
- OCR 默认块高 1200、重叠 120 像素，可在“更多选项”修改；结果明确标记完成、部分完成或失败。
- 结果面板保留图片预览，正文可复制或下载为浏览器本地 `.txt` 文件。
- “取消识别”、关闭结果或切换分析会取消在途请求；迟到响应不会覆盖后续分析。
- 关闭结果保留作品页码和筛选，不自动写回对话或启动生成任务。

支持 Core PNG/JPEG/WebP/GIF。模型沿用当前 Iris 视觉能力分配及既有候选规则；主动点击识别会请求模型，浏览列表不会。旧版图片保留打开和既有工具的文件路径输入；旧版作品 ID 与 Core ID 不混用。

看图、OCR 每块输入和定位按实际账号/模型准备发送副本，默认 8 MiB；大图保留 Core 原文件，只等比缩小发给模型的 PNG/JPEG/WebP。可在账号详情或模型行设置大小预算、最长边及恢复继承，见 [视觉输入预算](CLI_MANAGEMENT.md#看图输入预算)。展示、详情和下载仍读取原图；OCR 保留切片规则，结果标明缩小时的细字风险；定位返回已换算的原图像素。更新插件后需重新加载 DSH 后端并刷新客户端。

## 从图片卡改图

Core 静态 PNG/JPEG/WebP 图片卡增加“改图”。填写修改指令，可显式选择支持聊天生图的模型，或按现有候选顺序选择。面板只读取模型配置，不自动实测；只列出 `openai-chat-images` 生图模型，冷却/额度耗尽项不可选择。

点击“生成修改版”才调用模型，原图保留，修改版作为关联原图的新 Core 作品显示。成功后提供新 Artifact 链接、刷新作品库，保留筛选和页码；新作品可继续看图/OCR、编辑、下载和管理。来源最多 20 MiB；大图只处理发送副本，预算设置也可在聊天生图模型行编辑。

“停止等待”、关闭面板或切换分析会中止在途等待，迟到响应不覆盖新面板。远端可能已受理，须在任务区查看结果，不会自动再次生成。编辑任务的手动重试要求重新输入修改指令并确认原图 ID；只支持一次带图请求，不保存聊天历史或提供蒙版。详见 [CLI 改图](CLI_MANAGEMENT.md#artifact-聊天改图)。

## 查询与完整性

工作台使用同源 `GET /iris/api/works`，参数为 `offset`、`limit`（默认 24，最多 60）、`media_type`（all/image/video/audio/text）、`source`（all/core/legacy）和 `kind`（all 或具体产物类型）。服务端先过滤、按时间及来源/ID 稳定排序，再统一分页，返回 `items/total/offset/limit/kinds/counts`；客户端不再拼接两个已经分页的结果。

目录查询复用已提交的 Manifest 与派生 Index，只读取元数据和文件大小，不反复读取视频等媒体的完整字节、不重建索引或取得 Core writer 租约。打开媒体、看图/OCR、CLI inspect/list/export 保留原有完整内容哈希核验；目录里显示的哈希不表示本次浏览已经重新核验了全部文件内容。

OCR 动作 JSON 附 `status/totalChunks/successfulChunks/failedChunks/skippedChunks`，便于界面表达完整度。识别正文不自动保存为 Core Artifact。

## 选择、详情与批量下载

勾选作品卡或点击“选择本页”，显式选择最多 200 项。翻页和刷新保留选择，本页重复项不会重复加入；切换筛选清空选择。超过上限的整页选择会被拒绝，不截断或隐式选择所有匹配作品。

“复制选中 ID”每行一个 ID；旧版 ID 仍不能作为 Core Artifact 输入。“下载选中作品”把 Core 与旧版作品合为一个 ZIP，单次原文件合计最多 128 MiB。包内按 `core/<artifact_id>.<扩展名>` 和 `legacy/<作品ID>.<扩展名>` 命名，`works.json` 记录原文件名、来源、ID、MIME、字节数及 SHA-256，不携带本机路径、授权链接或提示词。所有选中项先预检，文件缺失或 Core 哈希失败时不返回部分 ZIP；保留原字节，不重编码图片或压缩媒体。可取消准备中的下载，大文件可继续使用 [CLI 批量导出](CLI_MANAGEMENT.md)。

每张卡的“详情”显示基本字段；Core 另展示完整 SHA-256、关联和尺寸/时间等安全元数据，并实际核验内容哈希。旧版只核验文件存在，不声称具有历史内容哈希。

## Core 回收区

Core 卡的“移入回收区”或“删除选中 Core 作品”先打开只读删除预览，再明确确认执行。批量删除只接受全部为 Core 的选中项；旧版保留原有单项永久删除与清空语义。

预览列出文件数、大小和引用阻塞。作品被任务记录引用时，可逐项明确勾选同时移除相关的已结束任务记录，再重新预览；未结束或结果未知任务不能勾选。任务仍关联未选中的其他作品、后续重试或外部产物关系时继续阻止删除，不自动级联或扩大选中集。

确认后复用 `core.delete` Command，将文件放入同一 Core 根的可恢复隔离目录。执行时重新核对事实和引用，成功返回事务 ID。“Core 回收区”列出删除与 CLI 清理事务；可明确确认恢复准备中、已隔离或中断的事务，恢复核对原哈希且不覆盖原位置冲突。已恢复/已回退事务保留记录但不能再次恢复。

隔离保留字节，不立即释放磁盘空间，也没有永久清空回收区入口。相同事务可使用 [CLI 管理命令](CLI_MANAGEMENT.md) 检查和恢复。这里只管理当前 DSH profile 的 Core，浏览/下载不请求模型。

新增内部同源入口：`GET /iris/api/works/{core|legacy}/:id`、`POST /iris/api/works/download`（`items:[{source,id}]`）、`POST /iris/api/works/delete`（`artifact_ids/task_ids/confirm_delete`）、`GET /iris/api/works/transactions`、`POST /iris/api/works/restore`（`transaction_id/confirm_restore:true`）。删除省略确认时只返回预览；执行与恢复必须显式确认，均沿用既有 Host/浏览器来源守卫。

## 验收状态与后续

0.2.1 已实现作品管理与图片卡改图。2026-10-09 的实现快照通过 163 个测试文件、263 文件 lint 与已安装 DSH rc.2 服务 31 项隔离检查；新增真实网关改图已分别通过 DSH 工具与工作台入口交付新 Artifact，来源哈希保持不变。正式版本包另执行仓库外安装与跨平台 CI，证据范围见 [迁移验证说明](DSH_CORE_MIGRATION.md#验证证据与限制)。

作品管理第二轮的历史快照（2026-10-08）通过 145 个测试文件、240 文件 lint、rc.2 服务 30 项，以及包外 100 命令和 140 文件候选包安装验证。程序化证据覆盖分页/过滤、客户端组件交互、ZIP 原字节与 CRC、删除引用保护、隔离/冲突恢复及工作台事务由独立 CLI 恢复。历史快照不代表最终 0.2.1 包已验收，详见 [迁移验证说明](DSH_CORE_MIGRATION.md#验证证据与限制)。

真实浏览器/移动端排版、播放器、剪贴板和下载体验仍待逐项验收；用户已有绘图/识图/TTS 的试用反馈不等于新作品卡和回收区已全部目视通过。后续拟以第三轮补这些检查、真实附件链路和异步重启/CLI 接管，当前尚未执行。收藏、标签和搜索列在 [后续路线图](ROADMAP.md#后续功能方向)。

更新本地插件后需重新加载 DSH 后端并刷新客户端，确保新路由和工具参数实际生效。
