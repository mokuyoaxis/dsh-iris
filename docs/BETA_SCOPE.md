# 0.3.0-beta.1 范围与兼容约定

本页定义 **0.3.0-beta.1** 的发行范围、最小插件契约与主要用户流程。使用准确版本或 npm `beta` 通道，稳定 `latest` 保留0.2.7；历史alpha.1没有新增网络、视频、调度与Provider工厂上下文v1。安装与升级入口见[发布说明](releases/0.3.0-beta.1.md)。

## 纳入的主要流程

| 用户入口 | 候选约定 | 继续保留的边界 |
| --- | --- | --- |
| 启动/登录 | Core明确启动，首次设置访问口令、记住设备、退出/刷新恢复 | 不修改其他harness配置；Token模式继续作为显式选项 |
| 模型服务 | 添加/编辑/停用/删除供应商，显式凭据来源、完整目录确认、按功能选择模型池 | 目录和近期成功不是永久健康承诺；无跨请求模型轮转；不默认读取其他宿主或.env |
| 网络出口 | 独立HTTP/HTTPS节点、固定/有序池、供应商绑定、owner页面/CLI/API/Doctor | 无绑定继承实际进程环境；显式失效不悄悄直连；SOCKS、系统TUN控制、地域自动分流和Clash自动配置不在范围 |
| 创作/作品 | 图片生成/已支持的编辑协议、ComfyUI声明参数，语音/转写、固定文生视频，原件预览/下载 | 协议及账号能力以实际目录/实现和实测为准；没有新增Core音乐/视觉持久流程或远端视频编辑 |
| 执行/恢复 | 单物理根单写者，持久Run/Task/Attempt/Operation，显式有界调度、原UUID/原任务接回、本地停止 | 调度缺省串行；并发与HTTP速率/远端受理数分别限制；unknown与交付失败不自动新生成；停止不证明远端停费 |
| MCP连接 | 通用stdio和Streamable HTTP，显式客户端预设，用户选择功能/工具/scopes，导出/检查/握手/撤销/缩权 | 配置检查、协议握手与真实Agent调用分别验证；不扫描harness、不默认授权或聚合第三方MCP服务 |
| 插件/Panel | Provider、持久业务、页面/设置挂载、作品渲染，共享主题/API/登录；保留整套Panel替换 | 可信代码，无市场/自动安装/热加载/任意插件设置仓库；页面挂载不自动授权业务 |

入口说明：[从零启动](CORE_QUICKSTART.md)、[模型服务](PROVIDER_SETTINGS.md)、[网络工作台](NETWORK_WORKBENCH.md)、[调度](MEDIA_SCHEDULING.md)、[MCP](MCP.md)、[插件开发](PLUGIN_DEVELOPMENT.md)。

## 最小插件兼容面

本轮冻结的是下列窄约定，内部模块与完整通用SDK不纳入冻结：

- Plugin/Adapter契约v0：稳定插件/贡献ID、各自独立版本、Core兼容范围、明确启用与授权、准确持久依赖及缺失/错版错误。
- Provider工厂上下文v1：Core提供当次解析的连接与借用fetch，管理完整方法的正文/多跳及关闭；插件不拥有Core队列、任务存储或网络资源管理。使用功能标记确认支持，详见[Provider最小契约](PROVIDER_PLUGIN_CONTRACT.md)。
- 持久业务通过公开有限Core命令和原Operation执行；页面、设置挂载与预览器使用公开浏览器端上下文。Node插件和Shadow DOM都不是安全沙箱。
- 变更上述可观察输入/结果、权限、生命周期或准确依赖语义时，先审查兼容性并更新相应契约/贡献版本，不把实现升级伪装成原版本恢复。

两类[独立模板](PLUGIN_DEVELOPMENT.md)分别验证业务/页面/PNG预览与真实异步Provider协议。旧窄Provider扩展保留原用法。内部文件不因随包存在而成为公开导出；不要绕过package exports依赖私有路径。

## 数据与平台

旧根不自动迁移；新音频/视频根与网络任务有明确版本门禁，不能让旧CLI写入它们。已发布DSH原工具和原CLI仍按既有范围使用，Core新音视频不自动加入DSH原生共享Flow桥。

Node最低声明为22.0.0。CI配置包含Ubuntu/Windows及最低/当前Node22；**工作流配置存在和历史CI成功都不能证明当前候选通过**。本机Termux/PRoot ARM64、真实浏览器、本地代理、实际供应商和原生Agent结果应分别记录。最终发布还需核对同一候选的完整测试、独立包消费者和标准平台矩阵，不能拿旧压测或一次握手替代。

自动配额/GC、复杂模型/出口加权轮询、更多宿主凭据桥、legacy统一迁移、全部供应商/GPU/手机/浏览器/harness认证继续后置；不因本页列出能力就宣称这些覆盖已完成。

## 源码验收与发行候选

文档中的 `node scripts/...`、`tests/...`、`npm test` 和 `npm run lint` 从源码仓库根运行；开发脚本与测试不随npm包根目录分发。安装用户继续使用包内CLI/Web/MCP入口，不能把源码验证命令当作已安装包的使用要求。

CI除Ubuntu/Windows、最低/当前Node22完整测试外，另在Ubuntu当前Node22构建真实tarball，检查包外插件/Provider与凭据/调度消费者、strict NodeNext公共类型，并用真实Chromium验证打包后的总览、凭据、视频与调度页面。缺少必需编译器或浏览器会使该发行检查失败；其他可选运行时的SKIP不计作通过。具体运行结果以对应提交的CI和发行记录为准，历史B5记录不代替本轮结果。
