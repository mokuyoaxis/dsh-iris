# Provider 出站网络基础（beta.1）

0.3.0-beta.1提供实例级请求端口，可通过独立CLI管理[出口节点与池](NETWORK_RESOURCES.md)，并显式启用[供应商绑定与HTTP/HTTPS代理](NETWORK_ROUTING.md)。**0.3.0-alpha.1 尚不包含这些增量。** N2已完成受控代理和原任务恢复验证，N3另接[网络工作台与Doctor](NETWORK_WORKBENCH.md)。默认继续使用原来的网络环境，不替换已配置的全局 `fetch` / dispatcher，不改代理环境变量或系统路由。

本页描述内部装配边界，不是已冻结的完整 SDK。网络客户端构造器不通过包的公开 `exports` 导出；第三方插件不应依赖私有文件路径。统一插件现在通过[工厂上下文 v1](PROVIDER_PLUGIN_CONTRACT.md)借用只读 `network.fetch`，见[独立万相模板](../templates/provider-starter/README.md)；该上下文与类型从beta.1提供，旧窄 Provider 扩展的 options 用法继续保留。

## 实例与完整操作

一个客户端持有显式的 `fetchPort` 及可选关闭回调；没有显式端口时，在每次请求发生时读取 `globalThis.fetch`，保持原调用行为。显式端口失败直接返回原失败，不自动换用全局请求、不重试、不切换供应商。

Configured Provider 的目录发现、提交、查询、取消（协议已支持时）、下载和输入上传，经同一客户端执行。一次完整操作只登记一次：等待响应正文、分页、上传策略后的对象存储请求、转写结果 URL 和媒体下载完成后才结束，收到响应头不算操作完成。错误映射仍为同步函数。

上传返回后无需使用的正文、转写结果下载的非成功正文会显式取消并等待释放。媒体下载先准备本地目录再请求上游，目录准备失败保留本地存储错误，不留下未读取的网络响应。

调用者拥有客户端的生命周期，关闭顺序为：停止接收业务并取消/等待 Core 在途工作，等待 Provider 注册实例的操作与释放，再释放网络客户端。网络关闭拒绝新操作，等待已登记操作结束后只调用一次关闭回调；已开始操作仍能进行第二跳请求。关闭失败保留并向调用者报告，不重新执行清理。任意插件若忽略取消信号，公共端口不能强制结束它。

路由管理器在后续解析发现配置修订或所引用的代理凭据变化时，也复用这一关闭机制回收旧客户端：已接纳操作保留原快照直到完整正文和多跳结束，新操作使用重新解析的客户端；同一身份不累计缓存历史版本。最终实例关闭包含所有仍在排空的旧客户端。详见[网络路由生命周期](NETWORK_ROUTING.md)；未增加后台强制超时或改变Task身份。

未发布维护版还覆盖网络文件失效、版本降级或configId替换：后续显式路由解析会退役旧路由客户端并保留原错误。网络文件有效且未变化时，另一调用方传错configId不会回收合法客户端。同一网络配置允许多个catalogId共存；单次解析不代表另一个目录已经废弃，仅替换供应商目录文件不会自动清扫其他目录缓存，最终由实例关闭排空。

直接使用请求函数的内部代码必须把完整正文处理放在同一次操作内；裸 `fetch` 不是独立的排空跟踪器。测试可注入受控请求实现；显式路由由实例持有的Undici客户端执行。Task操作还提供Core路线持久化端口，不依赖CLI或Web的可选观察回调。

## 当前接入矩阵

| 路径 | 当前源码支持 | 实际边界 |
| --- | --- | --- |
| DashScope Configured Provider | 目录分页、图片/视频/TTS/转写的已有提交与查询、上传策略及对象存储、结果 URL 与媒体下载共用客户端 | 保留原受理状态和超时；没有新增模型、协议或重试 |
| OpenAI Images / Chat Images / Responses Images | 现有目录、同步生成和已有产物下载使用注入端口 | 不因此新增异步查询、远端取消或原图编辑 |
| Gemini Web Music 网关 | 目录与既有同步生成使用注入端口，内联作品照常入库 | 是网关扩展协议，非官方 Gemini 音乐 API；没有新增持久 Music 流程 |
| ComfyUI Configured Provider | 沿用已有 `fetchPort`，目录检查、prompt/history/queue/view 使用同一客户端 | 保持已有 API 工作流及取消边界，无真实 GPU 新验收 |
| 模型目录刷新服务 | 显式传入客户端后，共用该客户端发现；进行中的请求按客户端及注册实例隔离 | 相同客户端仍去重；已有完整目录快照及持久绑定规则不变 |
| CLI / 服务共享候选与原 Task 装配 | 按Provider、模型、Task及明确的网络要求解析客户端，图片/视频/音频候选及原Task都走该端口 | 解析参数不含Key；包装目录必须匹配显式network-config，旧配置继续继承原环境 |
| Core供应商连接检查、模型实测、ComfyUI设置检查 | 显式解析该供应商客户端并保持目录包装 | 缺少匹配网络上下文会拒绝，不静默调用默认fetch |
| 旧DSH原生调用、DSH借用模型/浏览器 | 保留已有装配和宿主接口 | 尚未增加DSH网络资源管理；借用服务的实际出站归宿主管理 |
| 独立视觉模型端口 | 旧配置继续原有接口及fetch注入 | 包装目录明确拒绝尚未接入的视觉路径，避免绕过网络要求直连 |
| 统一插件 Provider | Core 传入工厂上下文 v1，只借出 fetch，并自动管理完整生命周期方法；缺失匹配的显式网络上下文时拒绝 | 插件须等待正文/多跳请求；不能自行 run/dispose；同进程代码仍可自行联网，这不是网络沙箱 |
| 旧窄 Provider 扩展 | 保留 options 与内部 Configured 装配的 transport / fetchPort 注入 | 不把新上下文签名强加给旧工厂；需要主动遵循旧端口约定 |

下载重定向沿用请求实现的策略，TLS继续校验。受控真实代理验证了HTTP→HTTPS产物重定向、代理/供应商认证隔离、两个供应商并发、环境及宿主dispatcher并存；这些测试不证明用户真实Clash或系统TUN的具体行为。

## 验证与后续

Core服务可显式装配[有界媒体调度](MEDIA_SCHEDULING.md)，按实例、供应商和模型共同限制请求。它在已有Undici dispatcher前排队，重定向每跳重新入门，正文结束才释放HTTP名额；继承出口继续借用原dispatcher，显式出口继续使用原实例代理。远端已受理数量由Core Task事实另行控制，不使用HTTP连接数代替；未知受理不因此重放。

以下测试和`scripts/`开发验收命令从源码仓库根运行，不随npm包分发。`tests/provider-network.mjs` 验证实例隔离、并发与单项取消、完整正文/多跳排空、关闭失败、无隐式回退和共享候选装配。`tests/provider-network-integration.mjs` 使用本地 HTTP 服务验证目录、实际 multipart 上传、提交/查询、转写结果和下载，并验证忽略的响应流在关闭前释放；不会访问真实供应商或生成计费媒体。原协议、目录、凭据与 Core 流程另作定向回归。

独立节点/池、私有环境认证引用、owner CLI与[N2绑定/持久任务要求](NETWORK_ROUTING.md)已进入beta.1。`scripts/verify-network-proxy.mjs` 和 `scripts/verify-network-task-proxy.mjs` 分别覆盖真实代理传输及Core/CLI/API、原任务跨进程恢复。[N3](NETWORK_WORKBENCH.md)复用实际Core客户端做有界GET与有限IP观察，静态读取不联网；不携带Provider Key，不代表模型实测。创建但未绑定不改变网络；显式失效不悄悄直连。系统TUN、用户Clash和第三方插件的任意流量不在当前可证明的控制范围内。
