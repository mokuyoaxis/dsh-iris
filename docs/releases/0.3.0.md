# Iris 0.3.0: a durable media workspace for Agents

Iris 0.3.0 brings the standalone Core workbench, generic MCP and explicit plugin contributions to the regular release line, alongside the native DSH plugin and headless CLI. It consolidates the 0.3 alpha/beta series and subsequent Agent-diagnostic maintenance. A regular release uses npm `latest` and a non-prerelease GitHub Release; preparing the source or a local archive does not publish it.

Once this exact version is published:

```bash
npm install @mokuyoaxis/dsh-iris@0.3.0
```

## Changes since 0.2.7

- **A standalone workbench.** Configure media services, confirmed model uses, function pools, works and client connections through Core Web. Password login and remembered devices support normal refresh/restart recovery. DSH retains its native tools and host lifecycle without requiring a second Core service.
- **Durable media flows.** Save and explicitly execute image generation/editing, speech, transcription, fixed text-to-video, vision and OCR flows. Run, Task, Attempt, Operation and Artifact identities support inspection and recovery. Reads and reconnects do not generate again; unknown provider acceptance is not permission to resubmit.
- **Explicit Agent access.** MCP supports stdio and Streamable HTTP over the same Core. Users choose media groups, tools and operation scopes; saved connections do not automatically gain new permissions. Connection-specific Skills explain the effective tool set.
- **Credentials, networking and scheduling.** Opt into environment-variable credential references, HTTP(S) nodes, fixed/ordered egress pools, provider bindings and owner diagnostics. Bounded scheduling separates HTTP dispatch, rates and remote tasks; the default remains serial and each physical data root has one writer.
- **Usable plugin examples.** Independent business/page/PNG-preview and Provider templates consume public exports. Minimal Plugin/Adapter v0 and Provider factory context v1 define identity, compatibility, exact durable dependencies and Core-owned resources. The full SDK and private module paths are outside that compatibility promise; plugins are explicitly selected trusted code.
- **More precise failure and recovery guidance.** Invalid network resources retire old routes without replay. Explicit model-not-found evidence stops later OCR chunks using that model. Safe task errors distinguish query success from historical task failure. DSH/MCP distinguish busy writers, missing Operations and permission denial, retain original request identities and explain read-only recovery.

## Upgrading and compatibility

Read the [upgrade guide](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0/docs/UPGRADING_0.3.md) before replacing 0.2.7 or a prerelease. Node.js **≥22.1.0** is required. The [twelve exact DSH versions](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0/docs/DSH_COMPATIBILITY.md) remain the declared host range; a normal release does not certify additional host combinations.

Existing roots are not migrated. Create a separate new v5 root with `flow init` and `execution init --vision` for the combined Core media/vision/OCR flows; see the [quickstart](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0/docs/CORE_QUICKSTART.md). Existing v3/v4 roots and MCP grants retain their original capabilities. Keep old CLI writers away from new-format roots, preserve private configuration and wait for in-flight work before replacing a writer.

Promoting beta.3 to 0.3.0 adds no production dependencies or persistent-format changes. It retains minimal plugin compatibility; it does not freeze every internal API or provide a plugin sandbox, marketplace or automatic migration.

## Validation and known limits

The [release process](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0/docs/RELEASE_PROCESS.md) requires complete tests, actual archive consumers and public types, five Chromium scenarios and the exact final commit's Ubuntu/Windows minimum/current Node 22 matrix. Historical beta CI or a local version change cannot prove those final checks passed. Publication separately binds the exact version, commit and archive and confirms npm visibility and channel identity.

Existing evidence includes real media tasks and original-identity recovery, DSH/Kimi vision/OCR sessions, and controlled tests for networking, scheduling, plugins and Web/MCP. These validate their recorded scope; they do not certify every provider, browser or Agent. No new paid-model run is implied by promoting this release line.

- **OCR joins retain overlaps.** In the [four-scene check](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0/docs/OCR_VALIDATION.md), dense text, a table and a predefined readable photo region met their criteria. Four long-image chunks were individually accurate, but their joined text contained 75 duplicate characters and failed the unique-full-text criterion (CER 12.93%). `complete` means execution coverage, not proofreading or deduplication. Cross-chunk deduplication is not implemented.
- **Environment pauses remain open.** Historical PRoot/CLI pauses and late watchdogs have not been explained by successful standard-platform CI or a later local rerun.
- **Coverage has explicit limits.** Live ComfyUI GPU inference and complete native Windows/WSL DSH-host smoke tests remain unverified. Core music, realtime translation, translated-image output, universal SDK guarantees and all-provider/client certification are deferred. Existing DSH/CLI media entries retain their documented scope.

The complete capability and compatibility boundary is in the [0.3.0 scope](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0/docs/BETA_SCOPE.md).
