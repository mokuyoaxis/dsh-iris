# Iris 0.3.0-alpha.1: a shared media workspace for Agents

This first 0.3 alpha adds an independent Core workbench, generic MCP access and explicitly selected plugin contributions to the existing DSH plugin and standalone CLI. Core owns execution, storage and recovery; users choose what each client can access.

The package remains `@mokuyoaxis/dsh-iris`, with Node.js 22.0.0 or later required. Install the exact prerelease or follow npm `alpha`; stable `latest` remains 0.2.7. Existing DSH host-version declarations are unchanged. New Core and plugin contracts are experimental and may change before stable 0.3.

```bash
npm install @mokuyoaxis/dsh-iris@0.3.0-alpha.1
npx dsh-iris --help
```

Follow the [Core quickstart](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-alpha.1/docs/CORE_QUICKSTART.md) for a new workspace and the [Agent guide](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-alpha.1/docs/AGENT_CORE_QUICKSTART.md) for setup instructions. Both have English text with Chinese headings. The detailed product guides are primarily in Chinese.

## An independent workbench

- A real creation UI, works library, client connections and model services share the same Core records. The default Panel supports light/dark themes, local backgrounds and mobile layouts. Distributed screenshots use built-in themes, without a personal background.
- Local password login and remembered devices survive normal restarts. Logout permits signing back in with the same password; it does not require a mobile browser to read a private Termux token file.
- Model services expose providers, per-function automatic/manual/disabled pools and a health spectrum. Providers support connection checks, opt-in service-lifetime keepalive, disable/restore and protected deletion. Configuration or connectivity is separate from a successful media test.

## Durable media and ComfyUI

- Image generation/editing and speech/transcription persist Runs, original Tasks and finite Operations. Stable request keys reconnect lost responses; refresh never silently submits media again. Execution, local stop and image selection remain explicit permissions.
- ComfyUI workflows expose declared scalar parameters, including LoRA model/CLIP weights and schema-driven choices. Both Core and DSH have dedicated controls. Iris talks to an existing ComfyUI service; it does not install ComfyUI or guess workflow/model identifiers.
- Core Skills add independent ComfyUI guidance: clarify the workflow and requested result, read actual descriptors, keep original task identities and distinguish an API model from a ComfyUI workflow. Skill installation remains explicit and protects local modifications.

## Generic MCP and selected plugins

- Official SDK stdio and Streamable HTTP transports share Core. Users select media groups, scopes and individual tools; client presets and exports do not scan disks, install clients or grant additional access. Keep the Core service running when using either transport.
- Trusted plugins can contribute Provider adapters, durable business operations, pages, settings forms and artifact renderers. Core checks identity, compatibility, lifecycle and persistent task dependencies; loading does not authorize execution.
- The optional contact-sheet plugin demonstrates public SDK access, durable execution, a real Web page and generic MCP calls. Image-input businesses share eligible PNG/JPEG/WebP sources up to 8 MiB within one data root. Other businesses' execution, history and stop controls remain separately authorized; a handler reads only its bound sources.
- Exact dependency pins, original request keys and stored output identities survive interruption. A missing plugin does not remove saved history or outputs; restarting or upgrading does not automatically replay business work.

## Reliability fixes

This release fixes provider-health edit conflicts, bounded JSON/media responses, interrupted writer-lease preparation, adapter cleanup and delayed metadata, delivery error categories, transient maintenance-reader errors and stale DSH refresh responses. Startup test waits use a monotonic clock; timeout evidence retains the original budgets and failures.

Validation includes controlled local HTTP services, persistent Core storage, public SDK consumers, official MCP clients over both transports, Chromium business flows and actual process-interruption recovery. These tests do not establish compatibility with every paid model, GPU deployment or client attachment renderer.

## Alpha boundaries and upgrades

- Existing roots are not automatically migrated. Initialize new execution/audio roots explicitly; one data root has one writer. The shared-root model is not tenant isolation.
- Native DSH keeps its own UI and host services. The alpha does not require stable DSH users to move their existing workspace into Core Web.
- Video, music and visual understanding retain their existing DSH/CLI entry points. Their new Core Web/MCP creation entries are not all implemented. Real ComfyUI GPU inference remains unverified here.
- This is not a stable plugin SDK, community marketplace or hostile-code sandbox. Provider URLs, redirects and HTTP endpoints remain an explicit trust/deployment boundary.
- Historical timing anomalies, linear history-validation cost and a specific DSH/Firefox download observation remain recorded. Later successful tests do not establish the cause of an earlier timeout.
