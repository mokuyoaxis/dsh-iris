# Iris 0.3.3: Durable music, i2v/s2v video, multimodal plugin auto-forms, local FFmpeg muxing and 25 verified DSH versions

Iris 0.3.3 completes the core multimodal creation loop across the standalone Core Web workbench, HTTP API, Headless CLI, and MCP (`music/v0`, `video-i2v/v0`, `video-s2v/v0`, and multimodal plugin operations with host-owned schema auto-forms), adds zero-cost local workflow bridges (video tail-frame extraction `mode: "last"`, local `ffmpeg` audio-video muxing `media mux`, Web inline controlled outbox export, and one-click cross-mode draft handoffs), expands verified DSH host compatibility from 12 to **25 exact versions** (`0.1.2-rc.1` through `0.2.2-rc.5`), and ships workbench UX polish plus stability fixes. This release also includes the **Nov 28 Anniversary Special Edition** M + iris emblem in the READMEs (strictly limited to `2026-11-28` and `Iris 0.3.3`). A regular release uses npm `latest` and a non-prerelease GitHub Release; preparing the source or a local archive does not publish it.

Once this exact version is published:

```bash
npm install @mokuyoaxis/dsh-iris@0.3.3
```

## Changes since 0.3.2

- **Durable music (`music/v0`), image-to-video (`video-i2v/v0`), and talking-head video (`video-s2v/v0`) across Core Web, HTTP API, CLI, and MCP.**
  - Reuses existing `v3+` (music) and `v4+` (video) execution roots with three independent MCP capability groups (`music`, `video-i2v`, `video-s2v`; unchecked by default and excluded from the frozen 12-tool `LEGACY_BRIDGE_TOOLS_V0` list).
  - Supports custom provider capability declarations via `supportsVideoMode(modelId, mode)`, explicit DashScope `parameters.resolution` forwarding for `video-i2v`, dual `derived-from` lineage edges on `video-s2v`, and strict single-submission `music/v0` with explicit `retried-from` lineage when starting a new retry draft.
- **Multimodal plugin extensions and host-owned schema auto-forms.**
  - Plugins can declare `artifactInputTypes`, `artifactOutputKinds`, and `artifact.lineage` (legacy plugins without `artifactInputTypes` stay restricted to ≤8 MiB static images with zero silent privilege expansion).
  - The workbench **Local Tools → 扩展业务** tab renders CSP-safe native controls directly from closed plugin `inputSchema` definitions—preserving boolean enums, required empty arrays (`minItems: 0`), string arrays, nested JSON objects, per-operation unconfirmed idempotency-key recovery across switches, inline outbox export, and lineage/handoff links without custom plugin frontend code.
- **Zero-cost local workflow bridges.**
  - **Tail-frame extraction (`mode: "last"`):** Extracts the actual final rendered frame of a saved video via `ffmpeg` (`showinfo` `pts_time` reporting, avoiding container/audio-duration drift) for immediate continuation into `video-i2v`, image editing, `video-s2v`, cropping, or lineage inspection.
  - **Local FFmpeg audio-video muxing (`media.mux`):** Combines an existing Core video artifact and audio/music artifact into a ≤32 MiB MP4 (`muxed-video`) via `POST /api/v0/local-media/mux`, CLI `dsh-iris media mux`, MCP `iris_core_mux_video_audio` (`local-media` group), and Web **Local Tools → 音视频合轨**. Supports `shortest` / `loop_audio` / `pad_silence`, `replace` / `mix` (padding shorter original audio with silence), and volume scaling (`0.1`–`2.0`), preserving lossless H.264 stream copy when video is untrimmed and writing dual `derived-from` lineage edges.
  - **Web inline controlled outbox export (`outbox.export`):** Reuses `--outbox-dir` atomic hard-link publication and UUIDv4 idempotency inside Run results, Local Tools, and plugin outputs, alongside an Overview summary table.
  - **One-click cross-mode handoffs:** Routes outputs directly into downstream drafts across Overview inbox, images (→ edit / i2v / s2v / crop), audio/music (→ s2v / mux / transcribe), and videos (→ frame extraction / mux).
- **Expanded DSH host compatibility (12 → 25 exact versions).**
  - Verified **13 additional exact DSH versions** (`0.2.1-alpha.5`, `0.2.1-rc.1`–`rc.5`, `0.2.2-alpha.2`–`alpha.3`, `0.2.2-rc.1`–`rc.5`, including `@deepseek-ai/dsh@latest`) at 35/35 against official published SDK packages, bringing the matrix to **25 exact versions** (see [DSH compatibility](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.3/docs/DSH_COMPATIBILITY.md)). `scripts/verify-dsh-host.mjs` also aligns with the `0.2.2+` tool executor pipeline.
  - `0.2.3-alpha.1` and `0.2.3-alpha.2` are explicitly excluded pending full host authentication and headless `/iris/render` verification.
- **Workbench UX polish and CI/test reliability.**
  - Groups the 12 creation modes semantically (Image / Video / Audio & Music / Vision & Analysis); displays source first-frame thumbnails and driving audio players on saved `video-i2v` / `video-s2v` Runs; fixes `video-s2v-create` dual-source recovery and draft preservation across mode switches; adds `T2V`/`I2V`/`S2V` badges, lazy first-frame covers, and client-side quick filtering in the Gallery; adds one-click **Copy ID** across Run facts, lineage nodes, Local Tools, and plugin outputs; fixes Overview outbox column alignment (`bytes` / `updatedAt`).
  - Upgrades `actions/upload-artifact` to `@v7` (Node 24 runner) and stabilizes Windows plugin ESM import URLs plus browser relogin navigation.

## Upgrading and compatibility

Iris 0.3.3 reuses existing `v3+` / `v4+` / `v5` execution roots with **no new production dependencies, no `v6` root migration, and no automatic expansion of existing MCP connection grants**. See the [upgrade guide](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.3/docs/UPGRADING_0.3.md) before upgrading.

- Node.js **≥22.1.0** remains required for Iris itself (follow the host Node requirement such as `>=24.9.0` when running inside DSH `0.2.2-*`).
- **Rollback warning (back up first):** Once a `0.3.3` recipe (`music/v0`, `video-i2v/v0`, `video-s2v/v0`), multimodal `plugin-*` artifact kind, or `retried-from` relation is written to a data root, `0.3.2` and older releases cannot read that root in place (`IRIS_FLOW_RECORD_INVALID`). Rolling back requires restoring a pre-upgrade backup directory.
- [Minimal plugin contracts](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.3/docs/BETA_SCOPE.md) (`Plugin/Adapter v0`, `Provider factory context v1`) remain backward-compatible across `0.3.x`.

## Validation and known limits

Final release checks require the full test suite, `npm run lint`, actual packed archive consumers and TypeScript types, **nine** Chromium workbench scenarios (`overview`, `provider-credentials`, `video`, `scheduling`, `vision`, `locate`, `summarize`, `local-tools`, `v033`), and the exact commit's Ubuntu/Windows minimum/current Node 22 CI matrix (see [release process](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.3/docs/RELEASE_PROCESS.md)). Local documentation or version changes do not substitute for final archive and CI verification.

- **Local FFmpeg and outbox requirements.** Video frame/tail-frame extraction and local audio-video muxing require `ffmpeg`/`ffprobe` on PATH (mux output cap 32 MiB); `--outbox-dir` requires same-directory hard-link support.
- **Strict `music/v0` retry boundary.** Core `music/v0` enforces 1 Run = 1 Task = 1 bounded submission with no implicit HTTP 502 retry; re-attempts create a new Run linked via `retried-from`.
- **Deferred items.** Favorites/tags/recoverable archiving, `0.2.3-alpha.*` DSH WebServer Peer auth adaptation, live ComfyUI GPU inference, native Windows/WSL full DSH-host smoke tests, and historical PRoot/CLI pause attribution remain open for subsequent work.

The complete capability and compatibility boundary is in the [0.3.3 scope](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.3/docs/BETA_SCOPE.md).
