# Iris 0.3.1: visual grounding, zero-cost local tools and MCP ergonomics

Iris 0.3.1 builds on 0.3.0 with conservative OCR overlap deduplication, zero-cost local media and headless HTML/SVG screenshot MCP groups, a read-only `--inbox-dir` large-file import path, durable visual grounding (`locate/v0`) and multimodal frame summary (`summarize/v0`) flows, and interactive Web visual grounding with EXIF-aware SVG overlays and one-click local cropping. A regular release uses npm `latest` and a non-prerelease GitHub Release; preparing the source or a local archive does not publish it.

Once this exact version is published:

```bash
npm install @mokuyoaxis/dsh-iris@0.3.1
```

## Changes since 0.3.0

- **Interactive Web visual grounding and zero-cost local crop.** Core Web adds the `视觉定位` creation mode (strict two-step save-then-execute with identity-only recovery that never stores target text in `sessionStorage`), EXIF-aware pure SVG `viewBox` overlays (`style-src 'self'` CSP compliant) in both the main stage and lightbox, toggleable box/scrim controls, collapsible pixel coordinate adjustment, one-click zero-cost `POST /api/v0/local-media/crop` with preview-retry reusing the saved artifact and preserving the crop receipt and adjusted crop rectangle when refreshing the same run via the workbench toolbar, and direct handoff of cropped PNG artifacts into edit, vision, OCR or follow-up locate drafts.
- **MCP `vision-locate` and `media-summarize` (v5 roots).** Durable `locate/v0` returns raw-pixel bounding boxes (`x1/y1/x2/y2` and `left/top/width/height`) that plug directly into local cropping. Durable `summarize/v0` composites 1–20 authorized video frames or static images (including mixed aspect ratios) into a timestamped contact sheet with optional explicit `transcript` text and zero implicit ASR billing.
- **Zero-cost MCP `local-media` and explicit `html-render`.** `local-media` exposes `iris_core_crop`, `iris_core_pixel_diff` (with heatmap artifacts and diamond provenance authorization), and `iris_core_video_frames` (requires system `ffmpeg`/`ffprobe`) strictly over Core `artifactId` values. Opt-in `html-render` (enabled only via `--browser-executable <absolute-path>`) renders self-contained HTML/SVG (≤1 MiB) inside a networkless, scriptless CSP sandbox into durable Core PNG artifacts via `iris_core_render_html`.
- **Read-only `--inbox-dir` for large media imports (MCP + Web).** Explicitly mounting an out-of-root directory via `--inbox-dir` lets authorized `inbox` MCP clients (`iris_core_inbox`, `iris_core_import_inbox_file`) and Core Web users import ≤20 MiB static images and (v3+) audio directly into Core without Base64 overhead or browser uploads, enforced by symlink checks (using `O_NOFOLLOW` when provided by the platform), `fstat` size caps, magic-byte checks, zero host-path exposure and private-directory overlap guards.
- **Conservative OCR cross-chunk overlap deduplication (`boundary-overlap/v0`).** Adjacent successful OCR chunks with physical pixel overlap now deduplicate unambiguous matching boundaries while conservatively preserving ambiguous or periodic repeats and retaining every raw chunk in the OCR JSON report with a `deduplication` summary.
- **MCP ergonomics and Core Web alignment.** `iris_core_runs` supports `kind` / `selection` filters; `iris_core_run_operations` paginates per-run operation history; `iris_core_operation` supports bounded read-only `waitMs` (0–10000 ms); `openWorldHint` is tightened to `execute`-scope tools only; Core Web Overview, Gallery, Health and plugin Web contexts sync v5 vision/OCR/locate/summarize entries without altering the frozen 12-tool `LEGACY_BRIDGE_TOOLS_V0` allowlist.

## Upgrading and compatibility

Iris 0.3.1 is a drop-in patch release over 0.3.0 with **no new production dependencies, no persistent data-root format migration, and no automatic expansion of existing MCP connection grants**. See the [upgrade guide](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.1/docs/UPGRADING_0.3.md) when upgrading from 0.2.7, 0.3 prereleases or 0.3.0.

- Node.js **≥22.1.0** and the [twelve exact DSH versions](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.1/docs/DSH_COMPATIBILITY.md) remain unchanged.
- Existing v1–v5 roots continue to work as initialized; `vision-locate` and `media-summarize` require a v5 (`execution init --vision`) root.
- `--inbox-dir` and `--browser-executable` (`html-render`) are strictly opt-in; existing services and saved MCP connections do not gain new capabilities unless explicitly configured and authorized.
- [Minimal plugin contracts](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.1/docs/BETA_SCOPE.md) (`Plugin/Adapter v0`, `Provider factory context v1`) remain compatible across `0.3.x`.

## Validation and known limits

Final release checks require the full test suite, `npm run lint`, actual packed archive consumers and TypeScript types, six Chromium workbench scenarios (`overview`, `provider-credentials`, `video`, `scheduling`, `vision`, `locate`), and the exact commit's Ubuntu/Windows minimum/current Node 22 CI matrix (see [release process](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.1/docs/RELEASE_PROCESS.md)). Local documentation or version changes do not substitute for final archive and CI verification.

- **OCR deduplication live retest remains pending.** Conservative `boundary-overlap/v0` deduplication is verified by deterministic unit and Core flow tests, but has not yet been re-measured against paid live vision models on the original 7-request long-image sample from [OCR validation](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.1/docs/OCR_VALIDATION.md). `complete` continues to indicate full chunk execution coverage rather than guaranteed proofreading.
- **Headless HTML rendering depends on an explicit local browser.** Real headless Chromium E2E checks ran on Linux ARM64; other operating systems, sandbox configurations, and external MCP clients remain bounded by their respective environments.
- **Deferred scope remains unchanged.** MCP artifact selection/controlled outbox export, Core durable music, image-to-video/S2V in Core Web/MCP, live ComfyUI GPU inference, native Windows/WSL full DSH-host smoke tests, and historical PRoot/CLI pause attribution remain open for subsequent work.

The complete capability and compatibility boundary is in the [0.3.1 scope](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.1/docs/BETA_SCOPE.md).
