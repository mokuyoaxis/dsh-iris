# Iris 0.3.0-beta.3: durable vision and OCR

Iris beta.3 adds durable vision and OCR tasks to the Core workbench, MCP and CLI. It uses npm `beta` and a GitHub prerelease; stable `latest` remains **0.2.7**.

```bash
npm install @mokuyoaxis/dsh-iris@0.3.0-beta.3
```

## Changes since beta.2

- **Save first, then execute.** Select a source-image Artifact, an explicit vision model and a question or OCR chunk budget. Web shows the saved input and OCR plan before a separate execution action. Creation and execution permissions remain separate; reading, refreshing or reconnecting does not call the model.
- **Keep the original task and results.** Core saves task identity, UTF-8 text and OCR reports. Results can be viewed and downloaded after restart. Delivery recovery uses the original task and Artifact IDs without repeating inference.
- **Show OCR completion accurately.** Reports retain chunk indices, coordinates, successful/failed/skipped counts and actual model-call counts. Partial output stays visibly partial. Stopping or restarting does not resume chunks or silently recognize the image again.
- **Explain unavailable models and task errors.** Explicit model-not-found responses record model health evidence, including after partial OCR success; later chunks stop using that unavailable model. Generic 404 responses do not block it. HTTP/MCP expose safe error summaries, and DSH distinguishes a successful status query from the saved task's error.
- **Improve network and test reliability.** Invalid or replaced network configurations retire old routes without replay. Network Doctor keeps its timeout on the minimum Node version. Asynchronous tests wait for task state, measure RPS at transport dispatch, and bound request and child-process phases.

## Workspace and compatibility

Initialize a **new, separate workspace** using `flow init` followed by `execution init --vision`; see the [quickstart](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-beta.3/docs/CORE_QUICKSTART.md) and [vision/OCR guide](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-beta.3/docs/VISION_FLOWS.md). The v5 root also supports existing image, audio and text-to-video flows. Older roots are not converted, and existing connections gain no new tools automatically. Select `vision` or `ocr` and the required read/create/execute/stop scopes explicitly.

The Node.js minimum remains **22.1.0**. Production dependencies, the supported DSH host versions and [minimal plugin contracts](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-beta.3/docs/BETA_SCOPE.md) are unchanged. Vision supports OpenAI-compatible Chat Completions image-input SSE; a configured model or directory response does not prove inference works. Realtime translation, translated-image output and automatic model substitution remain outside this release.

## Validation and known limits

Validation covers Core/API/MCP flows, text/report delivery, original task identity after restart, browser save-then-execute, package consumers, public types and permission limits. Three clear synthetic samples also passed real vision execution, followed by DSH/Kimi read-only checks. These samples do not establish general OCR or natural-photo accuracy.

Environment-specific PRoot/CLI pauses and late watchdogs remain under investigation. No new real ComfyUI GPU or Codex model-session validation is included. Platform results are tracked in [CI](https://github.com/mokuyoaxis/dsh-iris/actions/workflows/ci.yml); the [release process](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-beta.3/docs/RELEASE_PROCESS.md) binds the exact version, commit and archive and independently confirms npm publication.
