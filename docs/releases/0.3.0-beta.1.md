# Iris 0.3.0-beta.1: routing, scheduling and durable video

The first 0.3 beta builds on alpha.1's standalone Core workbench, generic MCP, ComfyUI and explicit plugins. It freezes the [minimal plugin contracts and main user flows](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-beta.1/docs/BETA_SCOPE.md) within this beta scope. The broader SDK remains experimental.

```bash
npm install @mokuyoaxis/dsh-iris@0.3.0-beta.1
```

The npm `beta` channel selects this release. Stable `latest` remains **0.2.7**, and `alpha` retains **0.3.0-alpha.1**. Follow the [Core quickstart](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.0-beta.1/docs/CORE_QUICKSTART.md) for a new workspace.

## Added since alpha.1

- **Explicit network resources and routing.** Manage HTTP/HTTPS proxy nodes and fixed or ordered pools, bind a Provider, and inspect the route recorded for a task. An owner-only Web/CLI/API Doctor separates local configuration from an explicit bounded GET check. Unbound Providers inherit the actual process network environment; Iris does not configure Clash, control system TUN or infer geographic suitability.
- **Opt-in bounded media scheduling.** One physical root still has one writer. Network waits can overlap while short writes remain serialized, with separate HTTP concurrency, dispatch-rate and unfinished-remote-task limits. The default remains serial. Unknown acceptance never triggers automatic resubmission.
- **Durable text-to-video in Core Web and MCP.** A new v4 root adds actual model candidates, size/duration inputs, original Run/Task/Operation recovery, local stop and MP4/WebM playback/download up to 32 MiB. MCP exposes standard resource links and checks authorization on each read. Image-to-video, S2V, music and vision retain their existing CLI/DSH entries.
- **Environment credential references.** Explicit `apiKeyEnv` configuration stores a variable name and resolves its value inside Core. Inline keys remain supported. Conflicting inline/env/DSH sources are rejected; workflow reports and model-directory imports protect captured credentials. No automatic `.env` loading or host-configuration scanning is added.
- **Independent plugin starters.** The package includes a business/page/PNG-preview starter and a Wan asynchronous Provider starter. Provider factory context v1 lends Core's network port and resolved connection; Core owns scheduling, lifecycle, persistent tasks and storage. Plugin identities, exact dependencies and client grants remain explicit.
- **Clearer MCP onboarding and plugin status.** The workbench connects selection/authorization, configuration export and connection checks. Generic stdio/Streamable HTTP remain available with explicit client presets. Configuration inspection, protocol handshake and actual Agent use are separate facts.

## Reliability fixes

Paid submissions do not automatically follow redirects or replay ambiguous requests. Queue rejection stays local to the affected Operation; accepted-task recovery preserves the original Attempt. Source-artifact permissions, multipart/Request interoperability, bounded MCP HTTP load, network-client retirement, media size checks and audio container metadata have been corrected.

Artifact index failures remain visible and recoverable. Normal commits refresh metadata without hashing the entire media library; explicit rebuild and media reads retain content verification. DSH screenshot delivery confirms that the requested Iris HTML route actually served the page before accepting a PNG. Video model families, transcription retries and the browser-only DSH client type declaration have also been aligned.

## Compatibility and validation

Existing roots and grants are **not migrated or expanded automatically**. Video requires an explicitly initialized new v4 root; network bindings use a separate versioned configuration. Keep compatible readers and a complete backup when trying a newer format. DSH's existing exact host-version range and Node.js minimum **22.0.0** remain unchanged.

Release checks cover the Ubuntu/Windows and minimum/current Node 22 matrix, actual tarball consumers, strict NodeNext public types and Chromium workbench scenarios. Controlled Providers and local proxies are distinguished from real accounts. Selected Alibaba Cloud image/video/audio paths have separate real-account evidence; this does not certify every model, account, GPU, browser or harness. Live ComfyUI GPU inference, automatic quotas/GC, weighted model/proxy rotation and a plugin marketplace remain outside this beta.
