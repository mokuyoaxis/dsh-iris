# Iris 0.2.4：图片续作、统一分配与新版宿主兼容

0.2.4让已有图片可以直接进入作品库并继续编辑，统一六类功能的模型选择规则，同时支持DSH rc.2与alpha.4。

## 升级前检查功能分配

图片、视频、TTS、Music、转写和视觉只使用各自明确分配的有序名单。名单为空时停止新调用，临时指定的模型也必须已分配，且只调用该项。以前依赖自动补入模型池的功能，需要在升级后明确分配模型。

供应商、模型池和已有名单保留，不自动迁移个人配置。旧任务仍绑定原模型查询和补交付；手动模型实测独立于生产名单。DSH默认视觉改为需要明确加入名单的“DSH 当前默认模型”，独立CLI不能调用该宿主资源。见 [完整升级说明](../FUNCTION_MODEL_ASSIGNMENTS.md)。

## 图片导入与原生Qwen改图

工作台“导入图片”、`iris_import_image` 和CLI `artifact import` 保存静态PNG/JPEG/WebP图片，最多20 MiB，返回持久作品ID。保留原字节和源文件，不调用模型；已有Core作品无需重复导入。见 [图片导入](../IMAGE_IMPORT.md)。

`iris_edit_image`、CLI和工作台改图支持DashScope原生Qwen edit/max/plus、2.0/pro系列及日期快照，继续支持聊天生图协议。模型还须具备image-gen能力并加入生图名单，具体账号与地域是否可用由服务端决定。`qwen-image-2.0-pro` 已通过真实CLI带图生成、取回与保存来源关系的实测。

原图只读，发送副本按账号/模型预算处理；修改版保存为独立作品并关联来源。原生Qwen输入副本另受10 MiB上限约束。编辑精度、输出尺寸由模型决定，不提供蒙版、多参考图或像素级保真保证。见 [Artifact改图](../CLI_MANAGEMENT.md#artifact-聊天改图)。

## DSH双版本兼容

支持准确版本 `0.2.0-rc.2` 和 `0.2.1-alpha.4`，manifest、可选客户端peer及Doctor同步。不要求已有rc.2用户升级宿主，也不据此支持整个0.2.x。Iris最低Node.js为22.0.0；DSH若要求更高，以宿主为准。见 [兼容矩阵与验证范围](../DSH_COMPATIBILITY.md)。

## 使用与验证范围

Agent工具增至17项，三项Skills的共享说明包含图片导入、严格分配和Qwen改图。Music仍是可选功能，本版未更换音乐来源或增加新的音乐协议。

宿主隔离验收覆盖实际官方SDK服务、工具/附件交付、HTTP与界面插槽；React/DOM和部分会话数据使用fixture，完整浏览器/移动端交互与热更新仍需实际使用验证。未增加Core数据格式迁移或生产依赖。
