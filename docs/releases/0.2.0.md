## Iris Media for DSH 0.2.0

Iris 0.2.0 brings the media runtime to the command line and adapts the DSH plugin to DeepSeek Harness `0.2.0-rc.2`. The npm package remains `@mokuyoaxis/dsh-iris`.

### Highlights

- Run crop, image diff, video frame extraction, image/video/speech generation and transcription without DSH. Inspect, observe and export tasks and artifacts across CLI processes.
- Share Core Task, Attempt and Artifact facts between the CLI, DSH tools and the workbench. Core owns the explicit data root, single-writer lease, lifecycle, cancellation and orderly shutdown.
- Add Artifact Manifest v0 with content hashes, relationships, a rebuildable index and orphan recovery. Core records keep prompts, credentials and private URLs out of durable task history.
- Share task controls across the CLI, API and workbench: observe again, redeliver, cancel where supported, and retry as a new task with explicit billing confirmation. Accepted or uncertain submissions never trigger automatic resubmission.
- Add read-only provider/capability listings, Core Doctor and explicit stale-writer recovery. Keep old task data intact; this release does not rewrite 0.1.4 storage in place.
- Preserve complete DSH attachment references, bind image-capable vision routes explicitly, handle stream errors, and follow rc.2 client main-view selection.
- Replace the floating bubble's pixel silhouette with a curved iris SVG, keeping existing status and interaction behavior.
- Publish bilingual agent quickstart prompts and separate installation instructions for current and older hosts.

### Compatibility and upgrade

- Node.js: `>=22.0.0`.
- DSH plugin: **exactly `0.2.0-rc.2`**, including the five optional client peers. Other rc versions and DSH 0.2.0 stable have no compatibility claim.
- Older DSH `>=0.1.2-rc.1 <0.1.3-0` or `0.1.5-rc.1`: keep using `@mokuyoaxis/dsh-iris@0.1.4`. Its historical Node minimum remains 20.10.0; do not follow npm latest on those hosts.
- Headless CLI: no DSH installation required. Video frame extraction needs `ffmpeg` and `ffprobe`.
- In dsh-market, check the full scoped package name, displayed version and host requirements. Marketplace caches may lag npm; a visible listing is not a compatibility guarantee.

Install on DSH rc.2:

```bash
dsh plugin --profile web add @mokuyoaxis/dsh-iris@0.2.0
dsh web
```

For the CLI in your own project:

```bash
npm install @mokuyoaxis/dsh-iris@0.2.0
npx dsh-iris --help
```

Download the older stable package separately with `npm pack @mokuyoaxis/dsh-iris@0.1.4`.

### Verification and current limits

Release checks cover 123 test files, Ubuntu and Windows on Node 22.0.0 and current Node 22, repeated minimum-version shutdown regressions, an isolated packed-package consumer without DSH, and isolated checks against installed rc.2 host services.

These checks do not establish complete personal-profile restart/rollback, every paid-provider path, native Windows DSH usage, or every Android browser action. Detailed boundaries remain in [the rc.2 adaptation notes](https://github.com/mokuyoaxis/dsh-iris/blob/v0.2.0/docs/DSH_RC2_ADAPTATION.md) and [the migration notes](https://github.com/mokuyoaxis/dsh-iris/blob/v0.2.0/docs/DSH_CORE_MIGRATION.md). Core internals and Model Port are not a frozen public SDK. The CLI observes one step at a time; it does not start a background service. Core Task/Artifact deletion is not exposed in this release.

Generation and transcription may consume provider quota or incur charges. The repository and package naming transition will follow a second real Host Adapter, with a new npm package at that point.
