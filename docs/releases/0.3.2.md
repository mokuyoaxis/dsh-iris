# Iris 0.3.2: MCP run selection, controlled outbox export, Web local tools and read-only lineage

Iris 0.3.2 completes the Agent MCP closing loop and expands the standalone Core Web workbench with explicit MCP image selection (`iris_core_select_run`), a controlled `--outbox-dir` export directory with crash-safe UUID recovery (`iris_core_export_outbox`), interactive Web video frame extraction and multimodal summary creation (`summarize/v0`), a zero-cost Web Local Tools panel (EXIF-aware arbitrary crop, two-image pixel diff heatmap, and opt-in HTML/SVG sandbox screenshot), and a read-only artifact/Run provenance lineage view. This release also records the live paid-model verification of `0.3.1` OCR overlap deduplication (`boundary-overlap/v0`). A regular release uses npm `latest` and a non-prerelease GitHub Release; preparing the source or a local archive does not publish it.

Once this exact version is published:

```bash
npm install @mokuyoaxis/dsh-iris@0.3.2
```

## Changes since 0.3.1

- **Explicit MCP image run selection (`iris_core_select_run`).** When Core is started with `--allow-selection` and local writes enabled, owners can explicitly grant `iris_core_select_run` (requiring `create` scope and the target Run's `image-edit` or `image-generate` group; unchecked by default and excluded from the frozen 12-tool `LEGACY_BRIDGE_TOOLS_V0` list). Clients pass `{ runId, expectedRevision, choice: 'source' | 'output' }` and rely on atomic revision checks (`409 IRIS_API_RUN_CHANGED` on stale revisions).
- **Controlled MCP outbox export (`--outbox-dir` + `outbox` group).** With local writes enabled, configure an existing writable directory outside the Core root. Authorized `outbox` connections call `iris_core_export_outbox` (`{ key, artifactId, name }`) to deliver verified images, audio, video, UTF-8 text or JSON. Core checks directory isolation and matches the filename extension to the media type recorded for the artifact. It stages the bytes in the target directory with POSIX mode `0600`, then creates the final name atomically using a hard link. An existing name returns `IRIS_OUTBOX_FILE_EXISTS`. Use the original UUIDv4 to recover the receipt after an interruption. If ownership cannot be confirmed, Core returns `IRIS_OUTBOX_UNCONFIRMED`. The target filesystem must support same-directory hard links.
- **Interactive Web video frame extraction and `summarize/v0` creation.** In Core Web with local writes enabled, saved video Runs expose a collapsible zero-cost frame extractor (`ffmpeg` / `ffprobe` on the Core host; 1–20 frames, target width, JPEG/PNG) with ordered timestamped thumbnails, lightbox zoom, exact-byte download, and checkbox selection into a `summarize/v0` draft (v5 roots) with optional question and user-supplied transcript text. Draft save preserves identity-only recovery across disconnects/refreshes with zero provider calls until explicit execution; execution uses the configured vision flow with zero implicit ASR calls.
- **Zero-cost Web Local Tools panel (`#tools-panel`) and owner-only geometry/directory APIs.** Adds a dedicated Local Tools sidebar tab and Overview shortcuts (preserving `style-src 'self'` CSP and zero `innerHTML`):
  - **Arbitrary EXIF-aligned crop:** Fetches owner-only `GET/HEAD /api/v0/artifacts` and `/api/v0/artifacts/:id/meta` (`imageGeometry` with APNG/40M-pixel guards and EXIF 1–8 orientation), projects the selection rectangle into both stage and lightbox `#expanded-overlay` via `locate-overlay.js`, submits raw pixel coordinates to `/api/v0/local-media/crop`, and supports preview-retry, exact PNG download, lineage inspection, and direct handoff to edit/vision/OCR/locate drafts.
  - **Two-image pixel diff heatmap:** Compares two workspace static images via `/api/v0/local-media/diff` with configurable grid (1–64, omitting empty cells on fine grids) and worst-region rankings (1–100), displaying heatmap PNG preview/download and explicitly noting that pixel difference is not a quality score.
  - **Opt-in HTML/SVG sandbox screenshot:** Strictly gated by `--browser-executable` and local writes (`session.htmlRender` + `html.render`); stays hidden with setup guidance and zero requests when disabled, renders inside the networkless/scriptless CSP Chromium sandbox when enabled, supports crop/creation handoff, and clears HTML input on logout.
- **Read-only artifact and Run lineage view.** Adds pure read-only Core projection (`lib/core-lineage.js`, including legacy metadata compatibility and strict produced-role classification) and owner-only `GET/HEAD /api/v0/artifacts/:id/lineage` and `/api/v0/runs/:id/lineage` (non-owner MCP connections receive `403`, zero silent grant expansion, zero disk migration). Core Web adds a default-collapsed lazy-loaded `#run-lineage` section in Run views plus inline artifact lineage inspection in Local Tools, supporting multi-hop artifact drill-down and direct navigation across upstream/downstream Runs.
- **Live paid-model verification of `0.3.1` OCR overlap deduplication (`boundary-overlap/v0`).** A bounded 4-request live `qwen3.8-flash` retest on the published `0.3.1` archive against the frozen 1000×2380 overlapping long-image fixture reduced unique full-text CER from `12.93%` (raw chunk concatenation, 75 duplicate characters across three overlap markers) to `0%` (`0/580`, `3/3` seams merged via `lines`, `0` ambiguous seams, all 11 critical fields and marker uniqueness passed, and zero extra outbound calls on post-restart UUID recovery). See [OCR validation](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.2/docs/OCR_VALIDATION.md).

## Upgrading and compatibility

Iris 0.3.2 is a drop-in update over 0.3.0 and 0.3.1 with **no new production dependencies, no persistent data-root format migration, and no automatic expansion of existing MCP connection grants**. See the [upgrade guide](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.2/docs/UPGRADING_0.3.md) when upgrading from 0.2.7, 0.3 prereleases, 0.3.0 or 0.3.1.

- Node.js **≥22.1.0** and the [twelve exact DSH versions](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.2/docs/DSH_COMPATIBILITY.md) remain unchanged.
- Existing v1–v5 roots continue to work without migration; `summarize/v0` requires a v5 (`execution init --vision`) root.
- `--outbox-dir` and `--browser-executable` remain strictly opt-in; existing MCP connections do not gain `iris_core_select_run` or `iris_core_export_outbox` unless explicitly enabled and selected.
- [Minimal plugin contracts](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.2/docs/BETA_SCOPE.md) (`Plugin/Adapter v0`, `Provider factory context v1`) remain compatible across `0.3.x`.

## Validation and known limits

Final release checks require the full test suite, `npm run lint`, actual packed archive consumers and TypeScript types, eight Chromium workbench scenarios (`overview`, `provider-credentials`, `video`, `scheduling`, `vision`, `locate`, `summarize`, `local-tools`), and the exact commit's Ubuntu/Windows minimum/current Node 22 CI matrix (see [release process](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.2/docs/RELEASE_PROCESS.md)). Local documentation or version changes do not substitute for final archive and CI verification.

- **Controlled outbox filesystem requirement.** Atomic non-overwriting publication in `--outbox-dir` requires a filesystem that supports same-directory hard links (verified locally on Linux F2FS and in cross-platform CI); filesystems without hard-link support cannot safely host `--outbox-dir`.
- **OCR live retest scope.** The 2026-11-23 live retest verified `boundary-overlap/v0` on the frozen synthetic overlapping long-image fixture (4 POSTs); it does not extrapolate to arbitrary natural multi-column documents, handwriting, or ambiguous real-world repeats. `complete` continues to indicate full chunk execution coverage rather than guaranteed proofreading.
- **Read-only lineage scope and deferred work.** Artifact/Run lineage in 0.3.2 is strictly read-only over existing persisted relations (favorites, tags, and recoverable archiving are not included). Core durable music, image-to-video/S2V in Core Web/MCP, neutral `TextModel Port` / standalone `prompt.optimize`, live ComfyUI GPU inference, native Windows/WSL full DSH-host smoke tests, and historical PRoot/CLI pause attribution remain open for subsequent work.

The complete capability and compatibility boundary is in the [0.3.2 scope](https://github.com/mokuyoaxis/dsh-iris/blob/v0.3.2/docs/BETA_SCOPE.md).
