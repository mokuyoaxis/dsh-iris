# 升级到 Iris 0.3（当前 0.3.3）

Iris 0.3 将独立 Core 工作台、通用 MCP、持久媒体与视觉流程、零计费本地工具、只读作品血缘、网络出口、有界调度与显式插件整合进正式版，同时保留原生 DSH 插件与独立 CLI。

## 升级前检查

- **Node.js ≥22.1.0**：0.3 线要求 Node.js 22.1.0 及以上版本（如 DSH 宿主版本要求更高，以宿主为准）。
- **确认入口与位置**：提前确认目标 DSH profile 或独立项目路径，以及现有数据根、私有供应商配置、认证目录与连接目录位置。0.3.3 的 DSH 支持范围已通过官方 SDK 实测扩充至[兼容矩阵](DSH_COMPATIBILITY.md)中的 **25 个准确版本**（覆盖 `0.1.2-rc.1` 至 `0.2.2-rc.5`；`0.2.3-alpha.*` 暂未纳入）。
- **排空并备份**：等待在途任务完成后再正常停止旧写者，并做好配置、数据根与凭据目录的备份。请勿手动删除租约、任务或旧工作区。
- **保留历史任务身份**：记下已受理或状态未知任务的原 UUID。升级、刷新或重连后，始终通过原 ID 只读查询进度，不要直接重新生成。

## 从 0.3.0 / 0.3.1 / 0.3.2 升级到 0.3.3

0.3.3 复用了既有 `v3+`（音乐）与 `v4+`（图生视频/数字人）执行根，不引入 `v6` 根、不新增生产依赖，且不会自动修改既有记录或扩展已保存连接的权限：

- **直接升级**：排空在途任务、备份现有数据根与配置目录、正常停止服务后安装新版本并按原命令重启即可；所有 `0.3.0`–`0.3.2` 历史 Run、Task 与 Artifact 保持只读和恢复兼容。
- **权限零静默扩张**：已有 MCP 连接保持原有工具与权限范围（旧版 12 工具 `LEGACY_BRIDGE_TOOLS_V0` 保持冻结）；如需开放 0.3.3 新增的 `video-i2v`、`video-s2v` 或 `music` 分组，请在连接中心或 CLI 中显式勾选并重新导出配置/Skill。
- **多模态插件与宿主自动表单**：未声明 `artifactInputTypes` 的旧插件保持仅限 ≤8 MiB 静态图片（零静默扩权）；新插件声明多模态输入/输出后，可通过工作台「本地工具 → 扩展业务」的宿主自动表单运行。

> [!WARNING]
> **回滚条件（务必先备份）**：在既有 `v3+` / `v4+` / `v5` 数据根中写入第一条 `0.3.3` 新流程（`music/v0`、`video-i2v/v0` 或 `video-s2v/v0`）后，`0.3.2`（及更早版本）严格校验 `flow-store/v0/runs` 时会因不认识新配方直接返回 `IRIS_FLOW_RECORD_INVALID`，导致**连同旧流程在内的整个流程列表都无法读取**。写入新多模态 `plugin-*` 作品类型或 `retried-from` 关系边后同样不可被旧版就地读取。如需回滚到 `0.3.2`，**必须使用升级前的完整备份目录（或切换到未写入 0.3.3 记录的旧数据根）**，不能仅降级 npm 包版本。

## 从 0.3.0 / 0.3.1 升级到 0.3.2

0.3.2 为 0.3.0 / 0.3.1 的平滑增量更新：

- **直接升级**：正常停止运行中的服务后安装 `@mokuyoaxis/dsh-iris@0.3.2` 并按原命令重启即可；不新增生产依赖，不修改 v1–v5 数据根磁盘格式，也无需重新初始化目录。
- **权限零静默扩张**：已有 MCP 连接继续保留原有工具与权限范围（旧版 12 工具 `LEGACY_BRIDGE_TOOLS_V0` 保持冻结）；如需为某条连接开放 0.3.2 新增的 `iris_core_select_run`（图片选定，需服务开启 `--allow-selection` 与本地写入）或 `outbox` 分组 / `iris_core_export_outbox`（受控出件），请在连接中心或 CLI 中显式勾选并重新导出配置/Skill。
- **显式启停开关**：受控出件目录需在启动命令中显式追加 `--outbox-dir <根外可写目录>`（部署目录须支持同目录硬链接，且需开启本地写入）；只读收件目录与无头 HTML 截图继续由 `--inbox-dir` 与 `--browser-executable` 显式开关。
- **工作台本地工具与只读血缘**：升级后工作台自动提供「本地工具」面板与默认折叠的「来源与派生血缘」区块，直接复用既有持久化 `Artifact.relations` 与 `FlowRun` 引用（含早期旧记录兼容元数据），无需迁移。

## 从 0.2.7 升级

### 原生 DSH 插件 / 独立 CLI

```bash
# 原生 DSH 插件（替换为实际使用的 profile；发布前请使用源码或本地归档）
dsh plugin --profile web add @mokuyoaxis/dsh-iris@0.3.3

# 独立 CLI / Core 项目
npm install @mokuyoaxis/dsh-iris@0.3.3
npx dsh-iris --help
```

升级 DSH 插件后，按正常流程重载插件后端并刷新浏览器页面即可。原有的 DSH/CLI 配置、Task、Artifact 与模型池策略均保持原样，不会因升级而被自动改写或静默启用新能力。

### 启用 0.3 Core 工作台与 MCP

0.3 不提供旧数据的自动迁移工具。如需使用独立 Web 工作台或 MCP，请按 [Core 快速开始](CORE_QUICKSTART.md) 选择一个**新的私有目录**，通过 `flow init` 与 `execution init --vision` 初始化 v5 执行根，再显式配置供应商与客户端连接。

| 现有工作区 / 配置 | 在 0.3.x 中的行为 |
|---|---|
| DSH / CLI 传统 Task 与 Artifact 根 | 继续沿用原入口读写；新工作台不会自动导入 |
| v0 只读 Flow 根 | 保持只读与选择能力，不就地转换 |
| v1 / v2 / v3 / v4 执行根 | 保持各自已初始化的能力；需要新能力（如看图/OCR/定位/摘要）请新建对应根 |
| 新建或既有 v5 执行根（`--vision`） | 支持图片、语音/转写/音乐（0.3.3）、文生/图生/数字人视频（0.3.3）与看图/OCR/视觉定位/多模态摘要 |
| 已保存的 MCP 连接授权 | 保持原有工具与权限范围，不会自动获得新分组或写权限 |

## 从 0.3 预发布版本（alpha / beta）升级

- **数据与契约**：beta.1–beta.3 的 Node.js 要求与持久格式延续至 0.3.x；现有执行根可直接沿用，也不会被自动升格为 v5。声明了精确兼容上限（不包含 `0.3.3`）的第三方插件需要由维护者更新兼容声明后方可使用。
- **诊断与恢复改进**：beta.3 之后补充了更清晰的拒绝错误码与只读恢复指引。`root_busy` 表示数据根当前有活动写者（并非已入队），遇到时应先以原 UUID 查回 Operation/Task；使用只读连接恢复历史 Operation 时，请保持 Core 执行服务开启。

## 升级后验证建议

1. 核对实际安装版本、Node.js 版本以及 CLI `--help` 或 DSH Host Doctor 状态。
2. 先对已有 Task/Artifact 与原 Run/Operation 执行一次只读查询，确认历史记录正常可读。
3. 检查供应商协议、模型用途、功能模型池及网络出口配置（目录可读不代表模型已经实测）。
4. 确认一切无误后，再按实际需要发起一次受控的媒体操作并核对产物交付结果。

> [!IMPORTANT]
> 降级 npm 包版本不会回退磁盘上的数据格式。请勿使用旧版本 CLI 写入新格式的数据根；需要回退环境时，请切换回对应的旧根或备份目录。

## 已知限制

以下限制在 0.3.3 中继续保留（详情见 [0.3 支持范围](BETA_SCOPE.md) 与 [OCR 质量验证](OCR_VALIDATION.md)）：
- 受控出件目录（`--outbox-dir`）依赖目标文件系统支持同目录硬链接；不支持硬链接的文件系统无法使用该功能。
- 保守 OCR 跨块边界去重（`boundary-overlap/v0`）已在正式 `0.3.1` 归档上完成冻结长图 4 次真实视觉 POST 复测（CER `12.93%` → `0%`），但单样本结果不能外推至任意复杂排版或存在歧义重复的自然文档；`complete` 仍代表所有分块执行完毕，不代表校对承诺。
- Core 音乐持久流程（`music/v0`）遵循严格 1 Run = 1 Task = 1 次有限提交（不做隐式 502 自动重试）；收藏/标签/可恢复归档、插件 SDK `1.0` 正式冻结、真实 ComfyUI GPU 推理以及全平台/宿主完整认证留待后续版本推进；PRoot/CLI 偶发停顿问题仍在持续跟踪。
