# 升级到 Iris 0.3.0

Iris 0.3.0 将独立 Core 工作台、通用 MCP、持久媒体流程、网络出口、有界调度与显式插件整合进正式版，同时保留原生 DSH 插件与独立 CLI。

## 升级前检查

- **Node.js ≥22.1.0**：0.3.0 提高了最低 Node.js 要求（如 DSH 宿主版本要求更高，以宿主为准）。
- **确认入口与位置**：提前确认目标 DSH profile 或独立项目路径，以及现有数据根、私有供应商配置、认证目录与连接目录位置。DSH 支持范围仍为[兼容矩阵](DSH_COMPATIBILITY.md)中的 12 个版本。
- **排空并备份**：等待在途任务完成后再正常停止旧写者，并做好配置、数据根与凭据目录的备份。请勿手动删除租约、任务或旧工作区。
- **保留历史任务身份**：记下已受理或状态未知任务的原 UUID。升级、刷新或重连后，始终通过原 ID 只读查询进度，不要直接重新生成。

## 从 0.2.7 升级

### 原生 DSH 插件 / 独立 CLI

```bash
# 原生 DSH 插件（替换为实际使用的 profile）
dsh plugin --profile web add @mokuyoaxis/dsh-iris@0.3.0

# 独立 CLI / Core 项目
npm install @mokuyoaxis/dsh-iris@0.3.0
npx dsh-iris --help
```

升级 DSH 插件后，按正常流程重载插件后端并刷新浏览器页面即可。原有的 DSH/CLI 配置、Task、Artifact 与模型池策略均保持原样，不会因升级而被自动改写或静默启用新能力。

### 启用 0.3.0 Core 工作台与 MCP

0.3.0 不提供旧数据的自动迁移工具。如需使用独立 Web 工作台或 MCP，请按 [Core 快速开始](CORE_QUICKSTART.md) 选择一个**新的私有目录**，通过 `flow init` 与 `execution init --vision` 初始化 v5 执行根，再显式配置供应商与客户端连接。

| 现有工作区 / 配置 | 在 0.3.0 中的行为 |
|---|---|
| DSH / CLI 传统 Task 与 Artifact 根 | 继续沿用原入口读写；新工作台不会自动导入 |
| v0 只读 Flow 根 | 保持只读与选择能力，不就地转换 |
| v1 / v2 / v3 / v4 执行根 | 保持各自已初始化的能力；需要新能力（如看图/OCR）请新建对应根 |
| 新建 v5 执行根（`--vision`） | 支持图片、语音/转写、固定文生视频与看图/OCR |
| 已保存的 MCP 连接授权 | 保持原有工具与权限范围，不会自动获得 `vision`/`ocr` 或写权限 |

## 从 0.3 预发布版本（alpha / beta）升级

- **数据与契约**：beta.1–beta.3 的 Node.js 要求与持久格式延续至 0.3.0；现有执行根可直接沿用，也不会被自动升格为 v5。声明了精确兼容上限（不包含 `0.3.0`）的第三方插件需要由维护者更新兼容声明后方可使用。
- **诊断与恢复改进**：beta.3 之后补充了更清晰的拒绝错误码与只读恢复指引。`root_busy` 表示数据根当前有活动写者（并非已入队），遇到时应先以原 UUID 查回 Operation/Task；使用只读连接恢复历史 Operation 时，请保持 Core 执行服务开启。

## 升级后验证建议

1. 核对实际安装版本、Node.js 版本以及 CLI `--help` 或 DSH Host Doctor 状态。
2. 先对已有 Task/Artifact 与原 Run/Operation 执行一次只读查询，确认历史记录正常可读。
3. 检查供应商协议、模型用途、功能模型池及网络出口配置（目录可读不代表模型已经实测）。
4. 确认一切无误后，再按实际需要发起一次受控的媒体操作并核对产物交付结果。

> [!IMPORTANT]
> 降级 npm 包版本不会回退磁盘上的数据格式。请勿使用旧版本 CLI 写入新格式的数据根；需要回退环境时，请切换回对应的旧根或备份目录。

## 已知限制

以下限制在 0.3.0 中继续保留（详情见 [0.3.0 支持范围](BETA_SCOPE.md) 与 [OCR 质量验证](OCR_VALIDATION.md)）：
- 长图 OCR 按分块顺序拼接，尚未对重叠部分去重；`complete` 代表所有分块执行完毕，不代表唯一全文。
- Core 音乐持久流程、完整插件 SDK 冻结、真实 ComfyUI GPU 推理以及全平台/宿主完整认证留待后续版本推进；PRoot/CLI 偶发停顿问题仍在持续跟踪。
